# The TypeScript client

`hippocampus-client` on npm is the TypeScript and JavaScript client: the contract's messages, enums
and service descriptor, generated by `protoc-gen-es`, behind [Connect](https://connectrpc.com)'s
client, over either of the service's two wires:

- **the JSON gateway**, anywhere `fetch` exists — a browser, a worker, Deno, Bun, Node, an Obsidian
  plugin; and
- **native gRPC**, from Node, which is the only one that can serve `Watch`.

One client type, two transports, every caller written once — the split the [`hippo` CLI](cli.md)
makes with its `--transport` flag.

**It is not on npm yet.** Every service release builds, tests and packs it, and attaches the tarball
to the GitHub release, but the upload has not been switched on. Until it is, install the tarball of
the release you run:

```sh
npm install https://github.com/fastbean-au/hippocampus/releases/download/vX.Y.Z/hippocampus-client-X.Y.Z.tgz
```

The first release carrying it is the one after v0.53.4.

```ts
import { createGatewayTransport, createHippocampusClient, wasStored } from "hippocampus-client";

const client = createHippocampusClient(
  createGatewayTransport({ baseUrl: "http://localhost:8080", token: process.env.HIPPOCAMPUS_TOKEN }),
);

const stored = await client.storeMemory({ body: "the deploy at 14:03 rolled back cleanly", significance: 50 });

if (wasStored(stored)) {
  const found = await client.searchMemories({ query: "deploy", limit: 5, reinforce: true });

  for (const memory of found.memories) {
    console.log(memory.body, memory.recallCount);
  }
}
```

The source is [`integrations/typescript/`](../integrations/typescript/).

## The two transports

```ts
// The JSON gateway: the server's gateway.port, which is 0 (off) by default.
import { createGatewayTransport } from "hippocampus-client";

const gateway = createGatewayTransport({ baseUrl: "http://localhost:8080" });

// Native gRPC, Node only. A separate entry point, so a browser bundle never pulls in node:http2;
// @connectrpc/connect-node is an optional peer dependency for the same reason.
import { createHippocampusGrpcTransport } from "hippocampus-client/grpc";

const grpc = createHippocampusGrpcTransport({ baseUrl: "http://localhost:50051" });
```

`npm install @connectrpc/connect-node` alongside the client to use the second.

The gateway transport does not restate a single route. Each call's verb, path, body binding and
query string come from the method's `google.api.http` annotation, read off the generated descriptor
— the same annotation grpc-gateway compiled the server's routes from — so there is no second copy of
the routing table to drift, and an RPC added to the contract is reachable over HTTP the moment the
client is rebuilt. A test holds every binding against the OpenAPI document the service generates.

**`Watch` needs gRPC.** It streams, and the gateway's calls are made in process, which cannot. Over
the gateway it is refused with `Code.Unimplemented` rather than attempted.

### A host with its own HTTP stack

`fetch` is a constructor option, which is how a host whose renderer enforces CORS plugs in its own
— Obsidian's `requestUrl`, for example, or a `fetch` bound to a proxy agent:

```ts
createGatewayTransport({ baseUrl, fetch: myFetch });
```

## What it covers

Everything the contract declares, because nothing here is written per RPC: the client is Connect's,
over the generated service descriptor. That includes the destructive and bulk RPCs (`purge`,
`clear`, `deleteMemoriesByFilter`, `transfer`) — this is a client library, and what a token may
actually do is the [service's tiers](configuration.md#authorisation) to enforce, the line the
Python client draws too.

Requests are plain objects or messages; responses are the generated message types, whose field
comments are the contract's documentation. Method names are the RPC names in lower camel case
(`StoreMemory` is `storeMemory`, `GetEventById` is `getEventById`).

## The four encodings

The wire's encoding is not what a caller means in four places, and `src/encoding.ts` has a helper
for each — the same four the Python client's dataclasses absorb:

| Wire | Meaning | Helper |
| :--- | :------ | :----- |
| UnixNano `bigint` timestamps | a time | `toNanos(date)`, `fromNanos(nanos)` |
| `0n` timestamp | **absent** — never recalled, not yet ended — not 1970 | `fromNanos(0n)` is `undefined` |
| tri-state `Bool` | `undefined`, `false` or `true` | `toBool`, `fromBool` |
| `"key=value"` metadata filters | an exact-match record | `metadataFilter({ role: "user" })` |

int64 fields are `bigint` throughout, never a lossy `number`.

## The three things that are the product, not faults

- **Insignificance is not an error.** A write below the deployment's `memory.minimumSignificance`
  is quietly dropped: the call succeeds with an empty `id` and `rejected: true`. Test the response
  with `wasStored(response)`; catching errors alone never notices.
- **Memories disappear.** Consolidation removes what has stopped mattering, so an id that existed a
  minute ago can be `NotFound`, and a recall of it simply does not return it.
- **Recall is a write.** `recallMemories`, and `searchMemories` with `reinforce`, reset the decay
  clock and raise effective significance. `getMemories` with `ids` is the read that does not.

See [Consolidation](consolidation.md) for why.

## Feature-detect with `whoAmI()`

What a deployment can serve — which search modes, whether it has an embedded summariser, whether
this instance is the consolidator — is reported by `whoAmI()`, and asking is cheaper than having a
call refused with `FailedPrecondition`:

```ts
import { SearchMode } from "hippocampus-client";

const identity = await client.whoAmI({});
const mode = identity.searchModes.includes(SearchMode.HYBRID) ? SearchMode.HYBRID : SearchMode.KEYWORD;
```

## Authentication, TLS and the client version

Both transports take the same identity options: `token` is sent as `authorization: Bearer <token>`
(see [authorisation](configuration.md#authorisation) for minting one), and `clientVersion` replaces
the default `hippocampus-client-typescript/<version>` the service shows on the
[topology view](clients.md#reporting-a-client-version). An application built on this package should
name itself there.

The gRPC transport takes `ca`, `cert`, `key` and `servername` for a service running with
`tls.enabled`, a private CA, or mutual TLS. Over the gateway, TLS is the host's `fetch` and an
`https://` base URL.

Both take `timeoutMs`, a default deadline for calls that name none of their own (a call's own
`{ timeoutMs }` option wins), and `interceptors`, Connect interceptors run around every call.

## Errors

Every failure, on either transport, is a `ConnectError` whose `code` is the gRPC code the service
chose — the gateway renders a failure as `{"code": <grpc code>, "message": ...}`, and the transport
turns it back. So one `catch` serves both wires:

```ts
import { Code, ConnectError } from "hippocampus-client";

try {
  await client.getEventById({ id });
} catch (err) {
  if (err instanceof ConnectError && err.code === Code.NotFound) {
    // gone - or, under group scoping, never yours; the two are deliberately indistinguishable
  }
}
```

`Unavailable` is routinely a purge in progress rather than an outage, and retrying is right.

## Versioning

The package version **is** the service release it was built from: `hippocampus-client@0.54.0` is the
client generated from the `v0.54.0` contract, published by the same release workflow from the same
tag — the Python client's rule. The generated code is **not committed**, so there is no second copy
of the contract to drift from it.

## Building it from a clone

`npm ci` installs the whole toolchain — `buf` and `protoc-gen-es` are devDependencies — and the
build generates `src/gen/` from [`contract/hippocampus.proto`](../contract/hippocampus.proto) before
compiling:

```sh
cd integrations/typescript
npm ci
npm test
```

`npm test` builds, type-checks the tests and runs them. Set `HIPPOCAMPUS_GATEWAY_URL` and
`HIPPOCAMPUS_GRPC_URL` to also run the live suite against a running service, which CI does on every
push.
